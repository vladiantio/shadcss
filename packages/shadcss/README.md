# shadcss

The CLI and registry for [shadcss](https://github.com/vladiantio/shadcss).

```bash
npx shadcss init
npx shadcss add button card field
```

## Commands

| Command | Description |
| --- | --- |
| `shadcss init` | Create `shadcss.json`, install the foundation files and generate `index.css`. |
| `shadcss add <items...>` | Install components and their registry dependencies. |
| `shadcss add all` | Install every stable component. |
| `shadcss list` | List stable components. |
| `shadcss list --all` | Include primitives and foundation items. |

`add` flags: `--overwrite`, `--no-deps`, `--html`, `--theme`, `--yes`.
`init` flags: `--css-dir`, `--entrypoint`, `--theme`, `--import`, `--yes`.

## Registry layout

```
registry/
  registry.json          # item manifest
  schema.json            # JSON Schema for the manifest
  tokens.css             # design tokens
  reset.css              # minimal reset
  base.css               # element defaults
  utilities.css          # sr-only
  primitives/            # shared popover and dialog shells
  components/            # structural CSS per component
  themes/nova/           # visual CSS per component
  examples/              # example markup used by `add --html`
```

Each component item contains:

- a base file in `components/` (structure and behavior),
- a theme file in `themes/nova/` (visual style),
- optional primitive dependencies,
- a root selector list,
- optional composition metadata.

`index.css` is generated by the CLI and declares the layer order:

```css
@layer shadcss.tokens, shadcss.reset, shadcss.base, shadcss.components, shadcss.theme, shadcss.utilities;
```

## Development

```bash
pnpm install
pnpm --filter shadcss build       # tsc -> dist/
pnpm --filter shadcss validate    # registry integrity + CSS parse
pnpm --filter shadcss examples    # regenerate registry/examples from the docs
pnpm --filter shadcss dev         # run the CLI with tsx
```

The registry is validated for:

- schema conformance,
- file and example existence,
- dependency resolution and cycles,
- `@layer` wrapping,
- forbidden Tailwind/legacy patterns,
- CSS parseability with Lightning CSS.
